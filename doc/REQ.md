# **專案需求規格書 (REQ): MFIVE 賞車網**

---

### **1. 專題介紹 (Project Overview)**

#### **1.1. 專題簡介**
「MFIVE 賞車網」是一個集中化、使用者體驗友善的線上車輛資訊平台。本專案旨在提供一個方便、快速的管道，讓使用者能輕鬆搜尋、比較並獲取最新、最完整的車輛資訊。

#### **1.2. 專題目的**
為了解決目前線上汽車資訊零散、規格比較不易的痛點，本平台的核心目標是優化潛在購車者的決策流程，並為汽車愛好者提供一個探索新車的優質社群。

#### **1.3. 背景**
隨著網路資訊的普及，消費者在購車前習慣於線上研究。然而，資訊來源分散（官方網站、汽車媒體、論壇），且規格比較功能往往不夠直觀。一個能整合資訊並提供強大比較工具的平台，將具有極高的市場價值。

### **2. 使用者分析 (User Analysis)**

#### **2.1. 使用者角色 (User Roles)**

本系統主要包含以下兩種使用者角色：

*   **會員 (Member / `USER`)**:
    *   **描述**: 網站的一般使用者，通常是潛在購車者或汽車愛好者。
    *   **痛點**: 找不到一個能快速比較多款車輛規格差異的平台；收藏感興趣的車款需要手動記錄，非常不便。
    *   **權限**: 瀏覽、搜尋、比較車輛、發表評論、收藏車輛。

*   **管理員 (Administrator / `ADMIN`)**:
    *   **描述**: 網站的維護者，負責管理平台內容的正確性與即時性。
    *   **痛點**: 需要一個簡單直觀的後台介面，來快速新增、修改、或下架車輛資料，並管理使用者帳號。
    *   **權限**: 擁有會員所有權限，並額外具備後台管理能力，包括管理所有使用者帳號及車輛資料。

#### **2.2. 使用情境 (Scenarios)**

*   **情境一：首次購車的社會新鮮人**
    *   **使用者**: 小陳，25歲，最近剛找到第一份工作，需要一輛預算在70萬內的代步車。
    *   **過程**:
        1. 小陳來到 MFIVE 賞車網，在首頁的搜尋框輸入價格區間 "0-70萬" 以及車身類型 "轎車"。
        2. 系統顯示了幾款符合條件的車輛，如 Toyota Vios, Honda Fit。
        3. 小陳將這兩款車加入「比較清單」。
        4. 在比較頁面，他清楚地看到兩款車在油耗、馬力、安全配備上的差異。
        5. 他對 Honda Fit 比較感興趣，於是點進詳情頁，查看更多用戶的評論。
        6. 最後，他註冊成為會員，並將 Honda Fit 加入「我的最愛」，方便日後與家人討論。

*   **情境二：追蹤新車的汽車愛好者**
    *   **使用者**: 阿傑，35歲，是個德系車迷，聽說 BMW 最近發布了新款 3 系列。
    *   **過程**:
        1. 阿傑直接在網站上搜尋 "BMW 3 Series"。
        2. 他在詳情頁看到了新款的詳細規格、高解析度圖集以及參考售價。
        3. 他在下方的評論區發表了自己的看法：「這次的改款頭燈更有侵略性了，期待試駕！」。
        4. 他將這款車加入「我的最愛」，以便追蹤後續的用戶討論。

*   **情境三：網站內容管理員**
    *   **使用者**: 管理員 David。
    *   **過程**:
        1. David 登入他的管理員帳號後，從導覽列進入「管理後台」。
        2. 他點擊「新增車輛」，並填寫剛剛上市的 "Ford Kuga 2025年式" 的所有規格資料與售價，並上傳了官方照片。
        3. 發布後，他回到網站前台，確認新車輛的資料顯示是否正確無誤。
        4. 接著，他進入「會員管理」頁面，將一位惡意洗版的會員帳號刪除。

### **3. 功能需求 (Functional Requirements)**

#### **3.1. 會員功能**
*   **F-U-01**: 使用者應能使用 Email、使用者名稱和密碼註冊新帳號。
*   **F-U-02**: 使用者應能使用帳號密碼登入系統。
*   **F-U-03**: 使用者應能登出系統。
*   **F-U-04**: 使用者應能瀏覽所有車輛列表。
*   **F-U-05**: 使用者應能透過關鍵字（品牌、型號）搜尋車輛。
*   **F-U-06**: 使用者應能查看單一車輛的詳細規格、圖片與介紹。
*   **F-U-07**: 使用者應能將最多三款車輛加入比較清單，並在專屬頁面並排比較規格。
*   **F-U-08**: 登入的會員應能將感興趣的車輛加入「我的最愛」。
*   **F-U-09**: 登入的會員應能查看自己的「我的最愛」列表，並可從中移除車輛。
*   **F-U-10**: 登入的會員應能對車輛發表評論。

#### **3.2. 管理員功能**
*   **F-A-01**: 管理員應能新增、修改、刪除車輛資料。
*   **F-A-02**: 管理員應能查看所有註冊會員的列表。
*   **F-A-03**: 管理員應能刪除會員帳號。
*   **F-A-04**: 管理員應能刪除不當的會員評論。

---

### **4. 非功能需求 (Non-Functional Requirements)**

*   **NF-01 (效能 Performance)**:
    *   網站主要頁面（首頁、列表頁）的載入時間應在 3 秒內完成。
    *   後端 API 的平均回應時間應低於 500 毫秒。
*   **NF-02 (安全性 Security)**:
    *   使用者密碼在資料庫中應進行加密儲存（目前為純文字，待改進）。
    *   所有使用者輸入都應進行驗證，以防止 XSS 或 SQL Injection 攻擊。
    *   管理員功能的 API 端點應有嚴格的權限驗證。
*   **NF-03 (易用性 Usability)**:
    *   網站介面應直觀易懂，使用者無需教學即可完成主要操作。
    *   網站應為響應式設計(RWD)，在手機、平板和桌機上都應有良好的瀏覽體驗。
*   **NF-04 (可維護性 Maintainability)**:
    *   前後端程式碼應遵循一致的編碼風格與架構模式。

### **5. MVP 功能 (Minimum Viable Product)**
*此為專案啟動後三週內必須交付的核心功能。*

1.  **使用者核心流程**:
    *   會員註冊與登入 (`F-U-01`, `F-U-02`)。
    *   車輛列表瀏覽與搜尋 (`F-U-04`, `F-U-05`)。
    *   車輛詳情頁查看 (`F-U-06`)。
2.  **核心比較功能**:
    *   加入比較清單 (`F-U-07`)。
    *   比較頁面 (`F-U-07`)。
3.  **後台管理**:
    *   管理員新增/修改/刪除車輛 (`F-A-01`)。

5. 人化功能**:
    *   加入/移除我的最愛 (`F-U-08`)。

### **6. 不在專案範圍內 (Out of Scope)**
*   **線上直接交易**: 不提供任何金流串接、線上簽約或汽車買賣功能。
*   **進階社群功能**: 初期不建立車主社群論壇、使用者評分系統。
*   **汽車金融與保險服務**。
*   **汽車零件與配件銷售**。
